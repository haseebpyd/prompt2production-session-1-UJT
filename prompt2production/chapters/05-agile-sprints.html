Chapter 5: Agile & Sprint-Driven Development

AI makes you fast — agile keeps you organized. This chapter covers agile basics, a full intro to PromptWizard (AlrightTech's sprint platform), sprint methodology, and ready-made Cursor prompts you can copy today.

5.1 Why Agile for AI Projects?

AI can generate hundreds of lines in seconds. Without structure, you get messy code, scope creep, and unfinished features. Agile gives you:

Clear priorities

Work on the most important feature first, every sprint.

Incremental delivery

Ship a working slice each sprint — not everything at once.

Feedback loops

Review what you built, adjust the plan, improve next sprint.

AI-friendly scope

Small, well-defined stories = better AI prompts and outputs.

5.3 User Story Template

As a [type of user],

I want [goal/feature],

So that [benefit/reason].

Acceptance Criteria:

- [ ] Criterion 1

- [ ] Criterion 2

Example for your main project:

As a registered user, I want to see a dashboard with my recent activity, so that I can quickly review what happened.

Acceptance Criteria:

- [ ] Dashboard loads after login

- [ ] Shows last 10 activities with timestamps

- [ ] Responsive on mobile and desktop

Part C — Sprint Methodology

5.10 The Four Foundation Files

Every client project starts with these markdown artifacts. Attach all four to Cursor Plan mode for every sprint after Phase 1.

context.md — What & Why

Executive summary, goals, user roles, feature list, scope (in/out), assumptions, risks.

Example: "PromptWizard standardizes intern onboarding — upload requirements → generate docs → track sprint progress."

tech.md — How (Stack)

Framework, database, auth, AI provider, API patterns, env vars, deployment target.

AlrightTech default: Next.js App Router + PostgreSQL + Prisma + Auth.js + Tailwind. Mobile: Flutter native or Capacitor for web-to-mobile.

uiux.md — Look & Feel

Color palette (hex + Tailwind tokens), typography, layout, component specs, accessibility, dark mode.

AlrightTech brand: navy #111424, cyan primary #00A7E1, pink accent #EC66B7.

sprint.md — When & What Order

Phases → sprints with Goals, Tasks, Acceptance Criteria, Stack Touchpoints (UI/API/DB), Dependencies, and a Sprint Execution Prompt block for Cursor.

Browse sprint-templates/ for full examples copied from PromptWizard.

5.11 Sprint Document Structure

Each sprint in sprint.md must be independently deliverable across UI, API, and database.

Section Purpose
### Sprint X.Y: TitleSprint name and phase
Goals1–3 outcomes for this sprint
TasksConcrete implementation checklist
Acceptance CriteriaCheckboxes — definition of done
Stack TouchpointsWhat changes in UI / API / DB
DependenciesPrior sprints that must be complete
Sprint Execution PromptCopy-paste block for Cursor Plan mode

5.12 Example Sprint (from PromptWizard)

Phase 2, Sprint 2.1 — Authentication. This is the format every sprint should follow:

### Sprint 2.1: Authentication & RBAC

**Goals** — Email/password auth, JWT sessions, ADMIN | INTERN roles.

**Acceptance Criteria**
- [ ] Intern can register and sign in
- [ ] Admin reaches /admin; intern cannot
- [ ] Passwords stored as bcrypt hashes

**Sprint Execution Prompt** (paste into Cursor Plan mode):
Implement Auth.js (credentials) per tech.md.
Deliver: login/register UI, JWT sessions with role, middleware.
Attach: context.md, tech.md, uiux.md

5.13 How to Execute a Sprint in Cursor

  1. Complete foundation docs — context, tech, uiux, sprint (via PromptWizard or manual).
  2. Open Cursor Plan mode — not Agent for your first sprints; Plan lets you review before applying.
  3. Attach foundation files — @context.md @tech.md @uiux.md
  4. Paste one Sprint Execution Prompt — only one sprint at a time; never the whole sprint.md.
  5. Review the plan — check files, scope, and that it matches acceptance criteria.
  6. Build → test → commit — git commit -m "feat: sprint 2.1 auth"
  7. Mark sprint done — update checklist in PromptWizard or your sprint.md checkboxes.
  8. Next sprint — repeat with the next execution prompt block.
