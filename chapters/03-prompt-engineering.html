3.2 Key Prompting Paradigms

Different approaches to structuring prompts for optimal results with LLMs.

Zero-Shot Prompting

Description: Providing no examples. The model uses its general knowledge.

Use Case: Simple summarization or factual questions.

Few-Shot Prompting

Description: Providing a few examples of desired input/output pairs before the main task.

Use Case: Guiding the model to a very specific output format (e.g., JSON or specific class structure).

Role-Based Prompting

Description: Assigning a persona to the model.

Use Case: "Act as a Senior DevOps Engineer" to get infrastructure recommendations.

Contextual Prompting

Description: Providing specific documents or code snippets the model must reference.

Use Case: Debugging a function by pasting the code and asking "Why is this crashing?".

Temperature & Creativity Control

Description: Adjusting randomness/creativity of responses (0.0 = deterministic, 1.0 = very creative).

Use Case: Low temp (0.2) for code generation, high temp (0.8) for creative writing.

Reactive Prompting (Iterative Refinement)

Description: Starting with basic prompt, then refining based on output in follow-up messages.

Use Case: Build complex solutions step-by-step through conversation and feedback loops.

3.4 The Prompt Coach

Not sure how to phrase a request? Paste this meta-prompt into any LLM first, then drop in your rough idea. The model rewrites it into a polished, structured prompt.

You are my Prompt Coach. I will give you a rough or unclear prompt.
Your task is to:
1. Clarify it
2. Add missing context
3. Structure it for best results
4. Suggest 2–3 alternative versions (simple, detailed, structured)

Here's my rough prompt: [INSERT YOUR PROMPT HERE]

Try it: Rough prompt = "make my app faster" → Coach returns a structured prompt with Role, Task, Constraints, and measurable goals.

3.5 Advanced Prompting Strategies

These techniques matter most for debugging, agents, and multi-step dev work. Each includes one practical example.

Chain of Thought (CoT)

Ask the model to reason step-by-step before giving the final answer. Improves accuracy on logic, math, and debugging.

When to use:

Bug diagnosis, algorithm design, complex refactors. Use temperature 0 for consistent reasoning.

Example — debug a React hook:

This useEffect runs infinitely. Think step by step: (1) identify the dependency array, (2) explain why re-renders trigger, (3) propose a fix with code.

[paste your useEffect code here]

Let's think step by step.
ReAct (Reasoning + Acting)

Interleave Thought → Action → Observation loops. The model plans, calls a tool (search, terminal, file read), reads the result, and continues. This is how Cursor Agent and most AI agents work under the hood.

When to use:

Tasks needing live data, multi-step verification, or tool use (API docs lookup, run tests, search codebase).

Example — find why API returns 401: Thought: I need to trace the auth flow from the login route to the protected endpoint. Action: Read src/lib/auth.ts and src/middleware.ts Observation: [model reads files] Thought: Middleware checks JWT but cookie name differs from login handler. Action: Propose a patch that aligns cookie names. Final Answer: [fix + explanation]
Step-Back Prompting

Ask a general principles question first, then apply the answer to your specific task. Grounds the model before it jumps to a solution.

Example — optimize a slow Next.js page: Step 1: "What are the key factors that affect Next.js page load speed?" [Get response: images, SSR, bundle size, caching...] Step 2: "Using those factors, recommend specific optimizations for my /dashboard page that loads 50+ product images." [paste relevant code or describe the page]
Self-Consistency (quick tip)

Run the same question 2–3 times with slightly different phrasing; pick the most common answer. Useful when a single CoT path might be wrong.

Example: "Generate 3 different reasoning paths for this SQL query performance issue, then select the most consistent fix."

3.6 Best Practices (Quick Reference)

Be specific

"Write a 300-word blog intro" beats "write about dogs."

Use action verbs

Analyze, extract, refactor, generate, classify.

Instructions > constraints

Say what to do; avoid long lists of "don't."

Define output format

JSON schema, markdown headings, code block only.

Iterate & document

A/B test prompts; save what works in your cheat sheet.

Low temp for code

Temperature 0–0.3 for deterministic output.

3.7 The 6-Step Prompting Framework (S-T-C-C-F-E)

The Power of Precision: The most important elements for getting functional code are Constraints (what not to do, e.g., "no external libraries") and Format (how to structure the output, e.g., "Output only JSON"). Review the complete framework on Panaversity GitHub or here.

Step Detail Example (Task: Write a Python function)
1. Role Assign a persona "Act as a world-class Python backend engineer."
2. Task State the core goal clearly "Create a function to calculate the Haversine distance between two coordinates."
3. Context Provide necessary background info "The application uses the math library, and coordinates are passed as a tuple (lat, lon)."
4. Constraints Set hard limits on the output "Constraint: Do not use any external libraries like geopy or scipy. Constraint: Add docstrings and type hints."
5. Format Specify the desired output structure "Output only the complete, runnable Python code, enclosed in a code block."
6. Examples (Optional) Show I/O pairs "Example: Input (40.6892, -74.0445) and (34.0522, -118.2437) should return approx 3935 km."
