Pro

Before writing code, understand how the web works. This foundation explains what happens when a user visits your app.

  • Internet — A global network of connected computers. Your app lives on a server; users reach it through browsers.
  • Browser — Software (Chrome, Firefox, Safari) that requests pages, runs HTML/CSS/JS, and renders the UI.
  • Server — A computer that hosts your app and responds to requests. Can be a cloud VM, serverless function, or container.
  • DNS — Translates domain names (e.g. myapp.com) into IP addresses so browsers know where to connect.
  • HTTP/HTTPS — The protocol for request/response. HTTPS adds encryption (TLS) — always use it in production.
  • APIs — Interfaces that let apps talk to each other. Your frontend calls APIs to get or send data.
  • JSON — Lightweight data format for APIs. Keys and values — easy for JavaScript to parse.
  • Cookies — Small text files stored in the browser, often used for sessions and preferences.
  • Storage — localStorage and sessionStorage let you persist data in the browser without a server.
  • CORS — Browser security rule: a page on domain A cannot call an API on domain B unless the server allows it.
  • CDN — Content Delivery Network — caches static assets (images, JS, CSS) near users for faster load times.
  • Security — Basics: HTTPS, never expose API keys in frontend code, validate input, use secure cookies.

HTML is the skeleton of every web page. Learn structure first — everything else builds on top.

  • Structure — Document outline: <!DOCTYPE html>, <html>, <head>, <body>.
  • Elements — Building blocks: headings, paragraphs, links, images, divs, spans.
  • Semantic HTML — Use meaningful tags (<header>, <nav>, <main>, <article>) instead of only <div> everywhere.
  • Forms — Inputs, labels, buttons, validation attributes. How users submit data to your app.
  • Tables — Rows and columns for tabular data. Use sparingly for layout — prefer CSS Grid/Flexbox.
  • Accessibility — Alt text, labels, keyboard navigation, ARIA when needed. Everyone should use your app.
  • SEO — Title, meta description, heading hierarchy, semantic markup — helps search engines index your pages.

CSS controls how pages look — layout, colors, typography, and motion. Master layout before frameworks.

  • Selectors — Target elements by tag, class, ID, attribute, or pseudo-classes (:hover, :focus).
  • Box Model — Every element is a box: content, padding, border, margin. Understand this to fix spacing bugs.
  • Flexbox — One-dimensional layouts (rows or columns). Great for nav bars, cards, centering.
  • Grid — Two-dimensional layouts. Perfect for dashboards, page sections, complex grids.
  • Responsive Design — Media queries, fluid units (rem, %, vw). Mobile-first approach.
  • Animations — Transitions and keyframe animations for polish — buttons, modals, loading states.
  • Variables — CSS custom properties (--color-primary) for theming and consistency.

Bootstrap is a component-based CSS framework. Ship responsive UIs faster with pre-built patterns.

  • Grid — 12-column responsive grid. container, row, col-* classes for layouts.
  • Components — Navbar, cards, modals, alerts, buttons — ready to use with consistent styling.
  • Utilities — Spacing (m-3, p-2), colors, display, flex helpers.
  • Responsive Layouts — Breakpoints (sm, md, lg) — same page works on phone and desktop.

Tailwind is a utility-first CSS framework — the default in this program. Compose designs directly in your markup.

  • Utility classes — Small single-purpose classes (flex, text-lg, bg-indigo-600) composed in HTML/JSX.
  • Responsive Design — Prefix classes with breakpoints: md:flex, lg:grid-cols-3.
  • Dark Mode — dark: variant for theme-aware styling. Pair with a class toggle on <html>.
  • Custom Theme — Extend tailwind.config with brand colors, fonts, and spacing — lock design in uiux.md.

JavaScript makes pages interactive. This is the core language of the web — invest time here.

  • Basics — Variables, types, operators, conditionals, loops, functions.
  • ES6+ — let/const, arrow functions, destructuring, spread, modules (import/export).
  • DOM — Document Object Model — select elements, change content, add/remove nodes.
  • Events — Click, submit, input, keyboard. Event listeners and event delegation.
  • Closures — Functions that remember variables from their outer scope. Powers callbacks and hooks.
  • Hoisting — How JS moves declarations — understand to avoid undefined surprises.
  • Event Loop — How async code runs: call stack, task queue, microtasks. Explains non-blocking behavior.
  • Async/Await — Clean syntax for asynchronous code — wait for API responses without blocking the UI.
  • Promises — Objects representing future values. .then(), .catch(), Promise.all().
  • Fetch API — Built-in way to call HTTP APIs from the browser. Returns a Promise.
  • Browser APIs — Geolocation, notifications, clipboard, Intersection Observer, and more.

TypeScript adds static types to JavaScript. Catch bugs early and improve editor autocomplete in large codebases.

  • Types — Annotate variables, parameters, and return values: string, number, boolean, unions, literals.
  • Interfaces — Define object shapes. Reuse across components and API responses.
  • Generics — Write reusable functions/components that work with multiple types: Array<T>, useState<T>.
  • Utility Types — Built-in helpers: Partial, Pick, Omit, Record — transform types without rewriting.

Version control is non-negotiable for professional development. Every sprint in this program uses Git.

  • Branching — Create feature branches (git checkout -b feature/auth) to isolate work.
  • Merge — Combine branch changes into main. Use pull requests for review.
  • Rebase — Replay commits on top of another branch for a linear history. Use carefully on shared branches.
  • PRs — Pull Requests — propose changes, get review, run CI checks before merging.
  • Conflict Resolution — When two people edit the same lines, Git marks conflicts. Open the file, choose the right code, commit.

React is the dominant UI library for building component-based interfaces. Used throughout the main journey.

  • Components — Reusable UI pieces. Function components return JSX.
  • Hooks — useState, useEffect, useRef, custom hooks — state and side effects in functions.
  • Context — Share data (theme, auth) across the tree without prop drilling.
  • Redux Toolkit — Predictable global state for complex apps. Slices, reducers, actions.
  • Zustand — Lightweight alternative to Redux — minimal boilerplate, great for medium apps.
  • TanStack Query — Server state: fetching, caching, refetching API data. Replaces most manual useEffect fetch logic.
  • Forms — Controlled inputs, validation libraries (React Hook Form, Formik).
  • Performance — memo, useMemo, useCallback — avoid unnecessary re-renders.

Next.js is the React framework for production — routing, SSR, API routes, and deployment built in. Default stack for intern projects.

  • App Router — File-based routing in the app/ directory. Layouts, nested routes, loading UI.
  • SSR — Server-Side Rendering — HTML generated per request. Good for dynamic, personalized pages.
  • SSG — Static Site Generation — HTML built at deploy time. Fast for marketing pages and blogs.
  • ISR — Incremental Static Regeneration — static pages that refresh on a schedule.
  • Server/Client Components — Server Components run on the server (no JS shipped); Client Components ('use client') handle interactivity.
  • Middleware — Run code before a request completes — auth checks, redirects, geo routing.
  • API Routes — Backend endpoints in the same repo. Keep secrets server-side.
  • SEO — Metadata API, Open Graph, sitemaps — built-in helpers for search and social sharing.
  • Auth — NextAuth.js, Clerk, or custom JWT flows integrated with App Router.

Frontends rarely stand alone — they consume APIs. Learn patterns for reliable data fetching.

  • Axios — Popular HTTP client with interceptors, defaults, and better error handling than raw fetch.
  • Fetch — Native browser API — no extra dependency. Works well with async/await.
  • Pagination — Load data in pages (offset/limit or cursor-based) instead of fetching everything at once.
  • Debouncing — Delay API calls until the user stops typing — essential for search inputs.
  • Caching — Store responses to avoid redundant requests. TanStack Query and SWR handle this automatically.

Most real apps need users to sign in. Understand tokens, OAuth, and access control.

  • JWT — JSON Web Token — signed token the client sends with requests to prove identity.
  • OAuth — "Sign in with Google/GitHub" — delegate auth to a trusted provider.
  • Protected Routes — Pages that redirect unauthenticated users to login. Middleware or layout guards.
  • RBAC — Role-Based Access Control — admin vs user vs guest see different features.

Fast apps keep users happy and rank better. Optimize after it works — measure first.

  • Lazy Loading — Load components and images only when needed (dynamic import, loading="lazy").
  • Code Splitting — Split bundles so users download only what the current page needs.
  • Memoization — Cache expensive computations and component renders when inputs haven't changed.
  • Web Vitals — Core metrics: LCP (load), INP (interactivity), CLS (layout shift). Target green scores in Lighthouse.

Tests give confidence to refactor and ship. Start with unit tests, add E2E for critical flows.

  • Jest — Test runner for unit tests. Assertions, mocks, snapshots.
  • React Testing Library — Test components the way users interact — click, type, assert visible text.
  • Playwright — End-to-end tests in a real browser — login flows, checkout, full user journeys.

Shipping to production is the goal. Automate deploys and manage secrets safely.

  • Vercel — Best fit for Next.js — git push to deploy, preview URLs per PR.
  • Netlify — Great for static sites and JAMstack apps with serverless functions.
  • CI/CD — GitHub Actions runs tests and deploys on every push — catch bugs before users do.
  • Environment Variables — API keys and secrets in platform settings — never in source code. Use .env.local locally.

Senior-level skills — how to structure large frontends that teams can maintain and scale.

  • Architecture — Folder structure, feature modules, separation of concerns (UI vs data vs utils).
  • SOLID — Design principles: single responsibility, open/closed, etc. — applied to components and modules.
  • Clean Code — Readable names, small functions, consistent patterns — code others (and future you) can understand.
  • Monitoring — Error tracking (Sentry), analytics, performance monitoring in production.
  • Micro Frontends — Split large apps into independently deployable frontend pieces — advanced pattern for big teams.
